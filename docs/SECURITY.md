# Безопасность

## Модель угроз

EzADB — ADB-хост. Получив доступ к целевому устройству, пользователь может выполнять команды с правами `shell`, устанавливать/удалять приложения, читать и изменять файлы и настройки. Это мощный инструмент; используйте его только на своих устройствах или с явного разрешения владельца.

## Ключ ADB

- Приватный ключ генерируется Kadb и хранится в `filesDir/adbkey.pem` приватного каталога приложения.
- Файлу выставляются owner-only права на чтение/запись.
- `android:allowBackup="false"` исключает попадание ключа в системный backup.
- Целевое устройство показывает RSA-fingerprint при первой авторизации; подтверждайте только знакомый ключ.

## Терминал и опасные действия

- Терминал выполняет произвольные команды на целевом устройстве.
- `RiskAssessor` распознаёт разрушительные шаблоны (`rm -rf /`, `dd of=/dev/...`, `pm uninstall`, `reboot bootloader`, критичные `settings put` и т.п.).
- При включённом подтверждении опасные команды и destructive-действия GUI требуют явного согласия.
- Отключение подтверждения не делает команды безопаснее — оно только убирает диалог.

## Сеть и USB

- Wi-Fi ADB должен использоваться в доверенной сети. Не оставляйте беспроводную отладку включённой без необходимости.
- Сопряжение Android 11+ использует SPAKE2 + TLS 1.3; код сопряжения одноразовый.
- USB-доступ запрашивается через системный `UsbManager.requestPermission`.
- mDNS-обнаружение только показывает имена/адреса сервисов в локальной сети.

## Демо-режим

Демо-режим работает полностью в памяти приложения. Он не открывает сетевых соединений и не выполняет команд на реальных устройствах. Все демо-данные помечены бейджем «Демо».

## Сообщения об уязвимостях

Создайте приватный security advisory в репозитории или свяжитесь с владельцем репозитория. Не публикуйте эксплойты в открытых issue до исправления.
